1. Scope

This architecture describes the minimal local RMS runtime in Phase 3 and defines how it evolves to Railway cloud deployment in later stages.

2. Architecture Diagram

The diagram shows browser interaction with Flask route layers, SQLite persistence for local versions, and the future move to Railway with PostgreSQL.

3. Runtime Components

  • Client layer: browser-based HTML pages for admin and planner workflows.
  • Application layer: Flask blueprints for common, admin, and planner routes.
  • Domain/data layer: database schema, DB connection lifecycle, and seed routines.
  • Data layer (local): SQLite file database.

4. Request Flow

  1. User accesses route from browser.
  2. Flask route performs role and input validation.
  3. Route executes queries against SQLite and applies business constraints.
  4. Route returns rendered HTML template with flash feedback.

5. Security and Access (Basic v1)

  • Role checks enforce admin-only and planner-only actions.
  • Session holds authenticated username and role.
  • Input validation prevents empty required fields and invalid allocation combinations.

6. Environment Separation

  • Local: Flask + SQLite for fast iteration and demonstrator usage.
  • Cloud target: Railway deployment with environment variables and PostgreSQL.
  • Migration path: keep route/domain design stable; swap DB backend and add migration scripts in a later phase.
