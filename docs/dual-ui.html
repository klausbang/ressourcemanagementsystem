Dual Interface: Simple and Modern

Back to Documentation Home

1. Purpose

RMS ships with two interfaces over the same routes and the same data: Simple (the original plain-HTML, zero-CSS, zero-JS interface) and Modern (a styled, tabbed, card-based interface with a small amount of unobtrusive JavaScript). Users switch between them at any time with a button present in both, and their choice persists for the session.

2. Why Keep Both

  • Simple stays as a minimal, dependency-free fallback and a quick way to see raw data with no styling opinions.
  • Modern is the primary, usability-focused experience: dashboards with quick stats, tabbed navigation instead of one long scroll, card-based multi-resource assignment, badges, empty states, and inline help.
  • Both interfaces submit to the exact same POST routes with the same field names, so there is only one implementation of business logic and validation to maintain.

3. How Mode Switching Works

  • The active mode is stored in session['ui_mode'] ("simple" or "modern", default "simple") via app/routes_common.py:current_ui_mode().
  • GET /ui-mode/<mode> sets the mode and redirects back to the referring page (including its query string, e.g. active sort/filter state), falling back to the resource catalog if there is no safe same-origin referrer.
  • Every view renders through render_ui(template_name, **context) instead of Flask's render_template directly. It resolves the template as f"{mode}/{template_name}", so admin_manage.html means templates/simple/admin_manage.html in Simple mode and templates/modern/admin_manage.html in Modern mode.
  • No route, no CRUD action name, and no form field name differs between modes — only the template selected to render the response.

4. Template Organization

app/templates/
  simple/   base.html, login.html, resource_catalog.html,
            admin_manage.html, planner_orders.html, help.html, _macros.html
  modern/   base.html, login.html, resource_catalog.html,
            admin_manage.html, planner_orders.html, help.html, _macros.html

Each mode has its own _macros.html with a same-signature sort_th(label, key, table_id, endpoint) macro, so route code and existing sort/duplicate-detection logic (app/table_utils.py) are unaffected by which mode is active.

5. Modern UI Design System

  • Assets: app/static/css/modern.css (self-contained, no CDN/network dependency) and app/static/js/modern.js (mobile nav toggle, flash auto-dismiss/close, confirm-before-delete via data-confirm attributes).
  • Layout: sticky top bar with branding, role-aware nav, a user/role chip, and the mode-toggle button; responsive down to narrow viewports via a hamburger menu.
  • Navigation within a page: Admin (Users / Capabilities / Resources / Capability assignments) and Planner (Customer orders / Ordered tests / Resource assignment) each use CSS-only radio-driven tabs — no JavaScript required for the core interaction, so it still works with JS disabled.
  • Resource assignment: presented as one card per ordered test with a removable chip per assigned resource and an "add resource" control, instead of one wide table row — chosen specifically because a test can now have several resources assigned at once.
  • Duplicate highlighting: same underlying _dup flag as Simple mode, styled as an amber row with a ⚠️ tooltip explaining what it means (via the modern _macros.html:dup_flag() macro).
  • Help: a dedicated /help page (role overview, admin/planner/technician workflows, table features, referential-integrity behavior) plus inline contextual copy (card subtitles, section-help notes, a callout on the resource-assignment tab) rather than a single wall of text.
  • Technician & test-report pages (Phase 7, Modern-only — see section 7): a tabbed technician dashboard (assigned tests / procedure library) built from the same card and chip components as the planner's resource-assignment tab; a test report page styled as a single A4 sheet with print-specific CSS (@page, chrome hidden under @media print); and a reports queue/history page reusing the standard modern-table styling.

6. Adding a New Page

  1. Add the route/view logic once, as usual.
  2. Call render_ui("your_page.html", **context) instead of render_template.
  3. Create templates/simple/your_page.html extending simple/base.html.
  4. Create templates/modern/your_page.html extending modern/base.html.

7. Exception: Modern-Only Pages

The technician workspace (app/routes_technician.py) and test reports (app/routes_reports.py), added in Phase 7, deliberately break the "one template per mode" rule above: they exist only under templates/modern/ (technician_dashboard.html, report_detail.html, reports_list.html), and their views call Flask's render_template("modern/...") directly instead of render_ui().

  • Why: this workflow — work orders, the fillable/printable A4 test report, and the review/approval queue — has no plain-HTML equivalent designed for it, and duplicating it into Simple would add real effort for a fallback mode nobody uses for this feature.
  • Consequence: these pages always render the same way regardless of the session's ui_mode, and the "Switch to Simple" button in the Modern top bar has no effect on them — a Simple-mode user who navigates to /technician/ or /reports/... still sees the Modern rendering.
  • Login behavior: because of this, common.login() forces session['ui_mode'] = 'modern' for the technician role specifically, so a technician never lands on a Simple catalog page with no visible way to reach their own workspace (Simple's nav is unconditional and has no Technician/Test Reports link).
  • If a future page needs true dual-mode support, follow section 6 instead of this exception.
