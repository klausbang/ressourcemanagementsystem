Help & Getting Started

Interfaces

This app has two interfaces showing the same data: Simple (plain, no styling, this one) and Modern (styled, tabbed, card-based). Use the "Switch to Modern Interface" link in the nav above to change. Your choice is remembered until you switch back or your session ends.

Roles

  • RMS Administrator (demo login: admin.demo): manages users, capabilities, resources, and which capabilities each resource has.
  • Test Planner (demo login: planner.demo): manages customer orders, the tests ordered under them, and which resources are assigned to each test.

Log in with just a username — this is a local demonstrator with no passwords.

Admin Workflow

  1. Create capabilities (e.g. "Vibration Test") and resources (equipment, facility, procedure, technician, etc.).
  2. Assign one or more capabilities to each resource so planners can find it for matching tests.
  3. Manage user accounts and their role (admin or planner).
  4. If two facility resources are really the same shared physical chamber, put them in the same exclusion group so the system can flag or block overlapping activities.
  5. Maintain reusable activity templates (e.g. "Standard EMC Test Sequence") — an ordered list of standard activities that a planner can apply to an order/EUT to bulk-create its test activities in one step.
  6. Record a technician's vacation/absence dates — the planner's Schedule tab and dashboard will flag it automatically.

Planner Workflow

  1. Create a customer order (order code, customer name, product name).
  2. If the order involves more than one physical unit, add each as an EUT (Equipment/Unit Under Test) — this is optional and can be left out for a simple, single-unit order.
  3. Add one or more ordered tests to that order, each optionally requiring a capability and optionally tagged to the EUT it belongs to — or apply an activity template to bulk-create a whole standard sequence in one step, then reorder or add/remove activities per project as needed.
  4. Assign resources to each ordered test. A test can have several resources assigned at once (e.g. equipment, facility, and a technician together) — only resources with the test's required capability are offered, and the same resource cannot be assigned twice to the same test.
  5. Check the Dashboard for an overview of every active project: its status and per-discipline status (generated from the underlying activities, not typed in separately), any live resource conflicts, activities still missing a work order or a test procedure, upcoming milestones, and customer on-site visits. The weekly note, "waiting for customer" flag, and customer visits are the only things set by hand there.

Table Features

  • Sorting: click any column header to sort by it; click again to reverse the direction.
  • Duplicate highlighting: a row shaded amber has the exact same values in every displayed column as another row in that table — a hint to check for an accidental duplicate entry.
