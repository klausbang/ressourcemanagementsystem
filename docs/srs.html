Resource Management System (RMS) - SRS v1

Version: 0.1 | Date: 2026-07-21

Back to Documentation Home

1. Purpose

This SRS defines the minimum requirements needed to build a first demonstrator of a web-based RMS for a small test company.

2. Business Context

  • The company performs electrical and mechanical tests on customer products.
  • The RMS supports planning and allocation of resources to customer orders.
  • Example orders include multimeter calibration and vibration/humidity tests for a mobile phone under development.

3. User Roles (v1)

  • RMS Administrator: manages resources, capabilities, and assignments of capabilities to resources.
  • Test Planner: assigns resources to customer orders.

4. Core Functional Requirements (v1)

4.1 Resource and Capability Management

  • The system shall store resources in these categories: test procedures, test equipment, test facilities, test technicians, administrators, and test planners.
  • The system shall allow administrators to create and update capabilities.
  • The system shall allow administrators to assign one or more capabilities to a resource.

4.2 Customer Orders and Allocation

  • The system shall allow creation of customer orders with one or more requested tests.
  • The system shall allow planners to assign available resources to each ordered test.

4.3 Access Control (Basic)

  • The system shall enforce basic role checks for admin-only and planner-only actions.

5. Data Requirements (v1)

  • Store users and roles.
  • Store resources and capabilities with many-to-many mapping.
  • Store customer orders, ordered tests, and resource allocations.

6. Non-Functional Requirements (v1)

  • Technology: Python with Flask.
  • Local first: working local version uses SQLite.
  • Cloud target: Railway hosting in later stage.
  • Documentation: SRS, architecture, ER model, development plan, and AI questions page in HTML.

7. Out of Scope for v1

  • Advanced scheduling optimization and conflict auto-resolution.
  • Test execution result capture and reporting workflows.
  • Production-grade identity management.
