Role focus: Test Planner

← Back to Customer Order Data Overview · Documentation Home

Purpose

One card per order, grouped into columns by its derived status — the same status the Dashboard already computes, so this view is just another way of looking at the same single source of truth, not a second place that could disagree with it. Closest in spirit to the customer's original Sprint.xls: a portfolio-level pipeline view across every active order, at the cost of activity-level detail (that still lives on the order's own page).

Wireframe only: dummy data, no working links, drag-and-drop, or forms — the column layout is the thing being proposed, not a drag-and-drop implementation (which would be a separate, larger decision).

Trade-offs

  • Good for: a fast, visual read of the whole pipeline — "what's stuck, what's moving, what's blocked" — and it reinforces that status is generated, not typed, by grouping on exactly that computed value.
  • Weaker at: activity-level detail (which EUT, which resource, which work order) doesn't fit on a card; a planner would still need to open the order for that, so this view works best as a landing/triage screen in front of Option A or C, not a replacement for either.
