RMS Documentation Style Guide (v1)

Back to Documentation Home

1. Required Page Structure

  1. Header with page title and link back to Documentation Home.
  2. Purpose section stating what the page covers.
  3. Core content sections in numbered order.
  4. Assumptions/Open Questions section where relevant.

2. Heading and Content Conventions

  • Use H1 once per page; use H2 and H3 for hierarchy.
  • Use short declarative requirement statements for SRS content.
  • Use explicit role names: RMS Administrator and Test Planner.
  • Use consistent term: Resource (correct spelling) in new docs.

3. Link and Navigation Rules

  • Every documentation page must link back to index.html.
  • Documentation Home must link to all core documents.
  • When a new doc is added, update index.html in the same change.

4. Diagram Rules

  • Architecture and ER diagrams should be embedded as PNG/SVG.
  • Each diagram must have a short textual explanation below it.
  • Use stable filenames and avoid duplicate diagram names.

5. Change Tracking

  • Update PROJECT_PLAN.md progress tracker when tasks are completed.
  • Add dated notes to the activity log for each completed phase task.
