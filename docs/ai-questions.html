Questions from AI tools to the product owner are listed here with priority tags:

  • Blocker - must answer now to continue current phase.
  • High - should answer in current phase.
  • Medium - can be deferred to a later phase.
  • Low - optional clarification.

Open Questions (from customer discovery, SRS v3)

  • [Medium] Should an EUT reference ever become mandatory on a test activity, or should it stay optional indefinitely for small single-EUT projects? (SRS FR-TP-2)
  • [Medium] Phase 9 seeded the two mutual-exclusion groups mentioned so far (CON: CE/CI, SAC: RE/RI) — is this the complete list, and are there equipment-level (not just facility-level) exclusions too? (SRS FR-CON-1)
  • [Medium] When shared equipment moves between TLC and TLS, is there a known minimum transit/setup time that should block back-to-back bookings at different sites? Phase 15 delivered a same-calendar-day warning as a coarse stand-in, not a precise buffer — would a real number let the check be tightened? (SRS FR-CON-3)
  • [Low] Is a spreadsheet/PDF export of a project's activities/results (FR-INT-1) actually needed by any external party, or does reporting stay inside RMS?
  • [Medium] Phase 10 seeded one standard activity template ("Standard EMC Test Sequence") covering the customer's example workflow — is more than one standard sequence needed (e.g. per product category or site), and should a template record which EUT/product types it applies to? (SRS FR-TP-4)
  • [Medium] Phase 11 seeded three disciplines from existing capabilities (Calibration, Environmental, EMC) plus two name-based fallback buckets ("Report" and "Project Management" for activities with no capability) — what is the confirmed full discipline list (the customer mentioned EMC, Radio, Safety, Report as seen in Sprint.xls), and should Radio/Safety be added once matching capabilities exist? (SRS FR-VIS-1, FR-STA-2 design note)
  • [Medium] Is "Waiting for Customer" the only externally-caused project hold worth its own flag, or are there others (e.g. "waiting on a spare part", "lab closed") that should get the same treatment rather than living only in the free-text weekly note? (SRS FR-PRJ-3)
  • [Low] Phase 12's schedule banner only flags absences/visits for the single day being viewed, plus a 14-day-ahead list on the dashboard — is a "this week at a glance" view worth adding so a multi-day absence/visit is visible without navigating into it day by day? (SRS FR-CAL-3)
  • [Low] Phase 13's activity history only logs schedule-affecting changes (resource assignment, reordering, EUT reassignment, work order lifecycle) — should test name/required-capability edits be logged too, and would a project-wide history view (not just per-activity) be useful? (SRS FR-NTH-1)
  • [Medium] Phase 14 scoped a dependency to within one project/order — is a cross-project dependency ever needed in practice? (SRS BR-006, FR-TP-5)
  • [Medium] Should an activity template (Phase 10) be able to pre-declare its own standard dependencies (e.g. "Report writing" always depends on every non-Report item before it in the same template), so applying a template also wires up dependencies automatically? (SRS FR-TP-5)
  • [Low] Phase 14's dependency block only fires at the work order start/resume transition, the same scoping rationale as FR-CON-2 — is a same-day, creation-time warning also wanted? (SRS FR-TP-5 design note)
  • [Medium] Phase 15's reschedule suggestions only trigger from a completed-late or currently-overdue prerequisite — is a suggestion also wanted the moment a prerequisite's work order is put on hold or marked failed, ahead of its planned end date actually passing? (SRS FR-RSC-2)
  • [Low] Phase 15 never re-suggests a reschedule for a (dependent, prerequisite) pair once accepted or ignored, even if the delay changes later — is a way to reset a dismissed suggestion needed, or is editing the planned dates by hand enough? (SRS FR-RSC-2 design note)
  • [Medium] Phase 16's order workspace deliberately excludes the day-view Schedule/Gantt tab (it's cross-order, not scoped to one order) and links out to the tabbed Planner page for it — is a per-order timeline strip worth adding directly to the workspace? (SRS FR-USE-6)
  • [Low] Should the tabbed Planner page's five tabs eventually be retired in favor of the order workspace plus the Orders Overview tab's portfolio-level List/Kanban/Master-detail views, or do both belong side by side for different working styles? (SRS FR-USE-6)
